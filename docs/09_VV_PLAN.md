# 09. Verification and validation

## 1. Test levels
| Level | What | Tools |
|---|---|---|
| Unit | Every decoder, rule, filter, parser, repository | `cargo nextest`, `proptest` (property tests for parsers and rule timing) |
| Rule engine | Every rule: fire, not-fire, persistence edge, gap restart (per-rule `max_gap_s`), hysteresis, supersession, multi-crew, unknown context (SR-018); absence-of-event rules with synthetic event streams; spot mode (SR-019): confirm, timeout and not-confirmed branches, n-of-m spot baselines, per-site and unknown-site temperature thresholds, THERMAL supersession | Exhaustive table-driven tests and property tests per rule, plus recorded corpora. Coverage gate: `caelum-alarms` ≥ 95 % region coverage. Nightly branch-coverage report (informational). Documented independent review of `caelum-alarms` |
| Golden files | XTCE output, CCSDS packets, FHIR bundles, audit entries | `insta` snapshots |
| Integration | Device emulator → ingest → alarm → escalation → downlink → ground profile decode | `caelum-test-equipment` |
| Interoperability | Real Yamcs instance decodes packets with generated XTCE; Open MCT plugin displays; FHIR validator accepts bundles; DICOM files open in reference viewer; CFDP transfers complete across contact windows | containers in CI |
| Hardware-in-the-loop | Real BLE devices (pulse oximeter, BP cuff, thermometer, HR strap, GHS device, wristband alert) on a test bench | bench runbook, nightly |
| Fault injection | Device disconnects, corrupt packets, clock jumps, disk full, DB corruption, primary crash, wristband absent, 30-day LOS (queue holds every item; CFDP transactions suspended at LOS and resumed at the next contact window) | scripted scenarios |
| Soak | 14 days continuous, 6 crew, full device load | metrics dashboard |
| UI components | Component tests, accessibility audit (axe), automated token contrast test (text ≥ 4.5:1, UI elements ≥ 3:1; light, dark and high-contrast themes), keyboard-only, 200 % text, glove mode | Vitest (jsdom); Vitest browser mode with Playwright (Chromium, WebKit) for axe |
| UI end-to-end | The real app driven through its WebView | `tauri-driver` + WebdriverIO on Windows (reference) and Linux; macOS gets component tests only |
| Usability | Formative tests, then summative evaluation (IEC 62366-1) with representative users | protocol in `docs/usability/` |
| Clinical review | Flight-surgeon review of ruleset and protocols; analog-mission trial | sign-off records |

MC/DC coverage is not measured: Rust has no supported tooling for it (CR-002 D3). The
compensating measures are the exhaustive per-rule tests, the coverage gates and the documented
independent review of `caelum-alarms`.

`caelum-test-equipment` provides device emulators that speak the same protocols as real devices
(BLE via a virtual adapter or loopback transport, DICOM sender, cFS packet source, Yamcs sink). It
is test equipment, not a product mode: release builds fail CI if the feature is enabled.

## 3. Traceability
`docs/trace.csv` columns: requirement ID, feature ID, milestone, code module, test names, result.
Generated by a script that scans test names and doc comments for IDs and joins the test results.
CI fails if an M-priority feature of a milestone marked `complete` in `10_BUILD_PLAN.md` has no
passing test. Features of other milestones are reported but not enforced.

Generator: `pnpm -C tools/ci trace` (`tools/ci/trace.ts`; `trace:check` in CI fails if the
committed CSV is out of date).
- **Catalog:** F-IDs and priorities from `01`, R- and N-IDs from `02`, SR-IDs from `06`; the
  milestone of an ID is every `10` milestone heading that names it; milestone status from the
  status table in `10`.
- **Citations:** a test cites the IDs in its name (Rust snake case such as `sr_012_…` counts),
  in the comment block directly above it, and in its file's header comment. Non-test source
  files that mention an ID are listed as code modules. Files whose header says
  `trace: ignore-ids` (the trace tool and its fixtures) are skipped.
- **Results:** joined from JUnit reports of cargo-nextest (`ci` profile), Vitest and node:test.
  Row result: `PASS` (cited by tests that all passed), `FAIL`, `NOT_RUN`, `NO_TEST`.
- **Errors (exit 1):** failing tests; an ID cited in code that the docs do not define; a test
  found in source but missing from every report; the milestone rule above.

## 4. CI pipeline
- fmt; clippy (`-D warnings`); nextest on Windows, Ubuntu and macOS.
- Coverage on stable Rust (`cargo-llvm-cov`): `caelum-alarms` ≥ 95 % region; other core crates
  ≥ 85 % line. A crate's gate applies from the milestone that implements it.
- Nightly-toolchain job: branch coverage for `caelum-alarms`, informational.
- UI: typecheck, lint, Vitest, contrast test; end-to-end tests with `tauri-driver` on Windows and
  Linux.
- Guards: release-feature guard (no `test-equipment`); write-exception guard (`caelum-vehicle`,
  `caelum-devices` against `docs/write-exceptions.md`); IPC bindings drift; trace check.
- Supply chain: cargo-deny, cargo-audit, pnpm audit (online on every run; air-gapped builds use
  the dated advisory snapshot in the tool cache), SBOM (CycloneDX).
- Offline reproducibility: release build from the tool cache with the network disabled
  (`docs/OFFLINE_BUILD.md`).
- Installers for Windows, Linux and macOS (signed from M13).
