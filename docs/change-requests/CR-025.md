# CR-025: Ground console profile and the Open MCT gateway

- **Status:** approved 2026-10-10 by engineering under the product owner's standing delegation.
  No new feature: F-GND-08 (ground console profile), the server side of F-GND-04 (Open MCT
  plugin), and the receiving end of CR-024. It is network code, so it is recorded here
  (CR-003 §5).
- **Affects:** `caelum-store` (V10), `caelum-core::station::console`, `src-tauri::console` (axum
  gateway; axum is already in the tree through `caelum-cluster`), `ui` (Ground screen).

## 1. Profile
An installation becomes a ground console when a signed `ground-console` bundle is applied. The
bundle gives:
- `receive`: UDP for downlinked packets from Yamcs or the agency MCS;
- `ack_to`: UDP for CFDP acknowledgements back toward the onboard instance;
- `gateway`: HTTP and WebSocket address for Open MCT;
- the mission's APID plan and CFDP entity IDs.

## 2. Intake
- Datagrams are parsed as Space Packets; telecommands and malformed packets are refused.
- **Summaries:** MEDICAL summaries go to `ground_summary`, once per crew member, parameter and
  window.
- **OPS records:** alarm, crew status and instance status go to `ground_ops` as the Open MCT
  plugin's message JSON, once per APID, sequence and packet time. New records go to the
  WebSocket stream.
- **Files:** CFDP PDUs are assembled by a receiving entity. Completed files go to `ground_file`,
  and ACKs, NAKs and Finished go back to `ack_to`.
- **Restarts:** partial transfers are not kept across a restart. Class 2 retransmission on the
  onboard side recovers them.

## 3. Gateway (Open MCT)
- **Endpoints:** `GET /history?type=&start=&end=` (UTC ms) and `GET /ws`.
- **Content:** OPS records only. That means no measured value, parameter name, rule ID or free
  text (R-SEC-06, verified by test).
- **Binding:** only the configured address, which must be on the mission-control console
  network. There is no physiology on this interface, so it carries no user sign-in. That is the
  same exposure as path B's OPS content.

## 4. Views and records
- **Flight surgeon:** downlinked summaries (min, mean and max, or the last state, with count and
  worst quality), received event packets, and OPS records.
- **BME and MCC:** OPS records only.
- **Private medical conference (PMC) record:**
  - drafted and edited by its author (flight surgeon);
  - signed once after re-authentication, then immutable (database trigger);
  - audited;
  - never visible to MCC.
