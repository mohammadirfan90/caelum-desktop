# CR-011: Technical-alarm limits and the self-test

- **Status:** approved 2026-10-10 by engineering under the product owner's standing delegation.
  Engineering values (not clinical). No new feature: the limits F-ALM-06 and the checks F-SYS-09
  need and the documents do not state.
- **Affects:** `caelum-alarms::technical`, `caelum-core` (self-test); F-ALM-06, F-SYS-09, SR-004,
  SR-012, R-OPS-04.

## 1. Technical alarms
| Cause | Rule | Raised when | Cleared when |
|---|---|---|---|
| Sensor off | SR-005 signal alarm | The device reports the sensor off or the signal unusable (CR-008) | A usable reading arrives |
| Low battery | `technical.low_battery.<device>` | Measured `battery_level` < 20 % | ≥ 20 % |
| Device lost | `technical.device_lost.<device>` | Disconnected ≥ 30 s (the link supervisor reconnects within 5 s, so this is a real loss) | Reconnected |
| Stale data | `technical.stale.<parameter>` | Newest value older than the catalog's `stale_after_s` (SR-004); a parameter never reported is NO DATA, not stale | A new value |
| Clock drift | `technical.clock.<device or station>` | Residual > 50 ms (R-OPS-04) or time going backwards (SR-012) | Back within the limit |
| Storage low | `technical.storage_low` | Free space < 1 GiB in the data directory | ≥ 1 GiB |
| Ruleset invalid | `technical.ruleset_invalid` | At load (SR-009) | A verified ruleset loads |

## 2. Self-test (start-up and on demand)
Checks: database integrity (`PRAGMA quick_check`), audit chain and signatures, ruleset verified
(fallback or safe state fail), clock gives TAI and the leap-second table covers now, free storage
≥ 1 GiB. Each failed check raises `technical.self_test.<check>`; passing again clears it. If the
clock itself fails, the alarm is still raised and its why says `time_known: false`.

## 3. Dependency
`fs4` 1.1 (MIT OR Apache-2.0, pure Rust) for free disk space; recorded in docs/third-party-risk.md.
