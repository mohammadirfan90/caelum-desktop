# CR-004 (PROPOSED): WebView2 distribution for offline-reproducible Windows builds

- **Status:** proposed by Claude Code on 2026-10-10 during M0 step 7. **Not approved.** Nothing is
  implemented until the product owner decides; `tauri.conf.json` keeps `offlineInstaller`.
- **Affects:** CR-002 D4, R-OPS-03, F-SYS-06, `docs/OFFLINE_BUILD.md`, `docs/03_ARCHITECTURE.md` §7.

## 1. Finding
CR-002 D4 chose WebView2 mode `offlineInstaller`, and R-OPS-03 requires release builds to be
reproducible offline from the tool cache. With Tauri CLI 2.12.1 these cannot both hold:

- To embed the WebView2 offline installer, the Tauri bundler first asks Microsoft's redirect URL
  (`https://go.microsoft.com/fwlink/?linkid=2124701`) for the installer's GUID, **on every build**,
  and only then checks whether the file is already cached
  (`%LOCALAPPDATA%\tauri\x64\<guid>\` for NSIS, `target\release\wix\x64\x64\<guid>\` for MSI).
- Evidence (2026-10-10, reference machine): with every proxy-respecting request sent to a closed
  local port and cargo offline,
  - `pnpm tauri build --bundles nsis` fails: `failed to bundle project: io: Connection refused`;
  - the same build with `webviewInstallMode` set to `skip` produces both the MSI and the NSIS
    installer, so NSIS and WiX themselves work offline from the cache.

## 2. Options
| | Option | Offline build | Install | Version control | Size |
|---|---|---|---|---|---|
| A | **`fixedRuntime`** for every Windows release build: a pinned WebView2 Fixed Version runtime from the tool cache, shipped inside CAELUM | Yes, officially supported, no network | One installer; works on LTSC 2019 without WebView2 | Pinned and tested with the app; CAELUM ships WebView2 security updates through its signed updates | Installer grows by the runtime (about the same as today's embedded installer) |
| B | `skip` in the CAELUM installer, plus the cached WebView2 offline installer delivered next to it and installed first by the installation procedure | Yes | Two steps (or a wrapper) | Not pinned: each laptop keeps whatever Evergreen version it has | CAELUM installer about 3 MB |
| C | Keep `offlineInstaller`; during offline builds answer Tauri's redirect request from a local stub proxy | Yes, but depends on Tauri internals | One installer | Not pinned | Same as today |

## 3. Recommendation
**Option A.** It is the only option that is offline, officially supported and pins the browser
engine that renders the safety UI to a tested version, which suits configuration control for flight
software. On an air-gapped vehicle Evergreen WebView2 cannot update anyway, so A loses nothing there.
The cost is that WebView2 security updates become CAELUM releases (a Fixed Version runtime should be
refreshed regularly to stay supported). Option C is not recommended: it would break silently on a
Tauri update.

## 4. If A is approved
- Tool cache: download the Fixed Version runtime `.cab` for x64, verify its Microsoft Authenticode
  signature (no hash is published), expand it, and record version and source in `ITEMS.json`.
- `tauri.conf.json`: `webviewInstallMode` `{ "type": "fixedRuntime", "path": … }`, with the path
  supplied by the build from the tool cache (the runtime is not committed to git).
- Update CR-002 D4, `03` §7, `docs/OFFLINE_BUILD.md`, and the config test in `src-tauri/tests`.
- Safety and test impact: none on alarm logic; install and launch test on Windows 11 and on
  Windows 10 LTSC 2019 without WebView2 at the M0 gate.
