# CR-008: Signal quality and flags from Bluetooth SIG profiles

- **Status:** approved 2026-10-10 by engineering under the product owner's standing delegation;
  items marked ⚕ are DRAFT under the provisional medical lead (CR-003). No new feature: these are
  the mappings F-ACQ-02 decoders need and the documents did not state.
- **Affects:** `caelum-devices` (`sig` decoders), ingest; F-ACQ-02, R-CLN-02, SR-005, SR-017.

## 1. Quality when a profile reports none
Quality is a qualifier, not a measured value, but it decides whether rules evaluate (SR-005).
When a profile has no status field (HTS, WSS, HRS without contact detection, BPS or GLS without
status, PLXS without either status field), the reading's quality is **`degraded`** ("not
reported"): rules still evaluate, and the UI does not show it as good. Never `good` by assumption.

## 2. Mappings
| Profile | Indicator | Quality / effect |
|---|---|---|
| HRS | contact supported, not detected | `unusable` |
| HRS | contact detected | `good` |
| PLXS | Measurement Status bit 13 (measurement unavailable) | no value (ingest rejects: missing value) |
| PLXS | bit 15 invalid, bit 12 calibration ongoing | `unusable` |
| PLXS | bit 14 questionable | `poor` |
| PLXS | bits 5, 6 ongoing / early estimate | at least `degraded` |
| PLXS | bits 10, 11 demonstration / testing | SR-017 flags: rejected in release builds |
| PLXS | Device and Sensor Status bits 1, 11–15 (malfunction, unconnected, unknown sensor, displaced, sensor malfunction, disconnected) | `unusable` |
| PLXS | Device and Sensor Status bits 2–8, 10 (irregularity, inadequate, poor signal, low perfusion, erratic, non-pulsatile, questionable pulse, interference) | `poor` |
| PLXS spot | flag bit 4 device clock not set | device timestamp discarded |
| BPS | measurement status: body movement, cuff too loose, improper position | `poor` |
| GLS | sample type 10, control solution | SR-017 test-data flag: rejected in release builds |
| GLS ⚕ | sensor status: malfunction, sample too small, strip errors, result above or below the device's range, read interrupted, device fault | `unusable` |
| GLS | sensor temperature too high or too low | `poor` |
| GLS | time fault | device timestamp discarded |
| All | IEEE 11073 special values (NaN, NRes, ±INF, reserved), WSS 0xFFFF | no value (ingest rejects) |
| All | GATT Date Time with unknown (0) date parts or out-of-range fields | no device time (receipt time used) |

## 3. ⚕ Open for the medical lead
- A glucose result outside the meter's range ("HI"/"LO") is not a number and is marked unusable.
  Whether it should raise its own alarm (it can mean severe hyper- or hypoglycaemia) is for the
  medical lead; until then it appears as a rejected reading in device health, not as a value.

## 4. Multi-user devices
BPS and WSS can carry the device's own user number. Decoders report it (`device_user`); the
device registry (M2) accepts readings only from the user slot assigned to the crew member, so a
cuff or scale shared by crew cannot file one person's reading under another.
