# CR-020: Local evidence replaces CI on milestone gates while CI is off

- **Status:** approved 2026-10-10 by the product owner (Mohammad Irfan) under the standing
  delegation. Process change only. No feature, interface or safety rule changes.
- **Affects:** `docs/10_BUILD_PLAN.md` (gate evidence), `docs/gates/*.md`, `docs/PROGRESS.md`,
  M13 release checklist.

## 1. Reason
The repository's GitHub Actions quota is used up. Every push since 2026-10-10 carries `[skip ci]`.
Without this change, milestone gates that name a green CI run could not close, although the same
checks can be run on the development station.

## 2. Decision
Until the product owner says otherwise, a gate condition that asks for a green CI run is met by
the full local pass below. It is run on the commit being gated, on the development station.

| # | Check | Command |
|---|---|---|
| 1 | Clippy, default build | `cargo clippy --workspace --all-targets -- -D warnings` |
| 2 | Clippy, test-equipment build | `cargo clippy -p caelum-core -p caelum-desktop --all-targets --features test-equipment -- -D warnings` |
| 3 | Rust tests, workspace | `cargo nextest run --workspace` |
| 4 | Rust tests, test-equipment crates | `cargo nextest run -p caelum-store -p caelum-ingest -p caelum-core --features test-equipment` |
| 5 | UI typecheck and lint | `pnpm -C ui typecheck`, `pnpm -C ui exec eslint src tests` |
| 6 | UI unit tests | `pnpm -C ui test` |
| 7 | UI browser suite (axe WCAG 2.1 AA in every theme, 200 % text with glove mode, keyboard walkthrough) | `pnpm -C ui test:a11y` |
| 8 | Release-feature, write-exception and npm licence guards, and their self-tests | `pnpm -C tools/ci check`, `pnpm -C tools/ci test` |
| 9 | Licences, bans, advisories and sources | `cargo deny check` |
| 10 | Traceability (every suite, `docs/trace.csv`, complete milestones enforced) | `pnpm -C tools/ci trace` |

What the local pass does **not** replace:
- the release-installer build on Windows and Linux runners;
- online `cargo audit` and `pnpm audit` runs: `cargo deny check` covers advisories from the
  local advisory database, which is as fresh as its last fetch;
- the hardware-in-the-loop bench;
- the end-to-end run;
- the Yamcs container gate;
- any gate condition that is not "CI is green".

## 3. Records
Every gate record (`docs/gates/Mx.md`) that uses local evidence gives:
- the commit and the date;
- the result of each check above with its pass counts;
- the statement "local evidence under CR-020".

## 4. When CI returns
A CI run on the then-current `main` is required before any release (M13). It must be green on
every workflow, including the release-installer jobs. A failure there reopens the milestones its
checks belong to.
