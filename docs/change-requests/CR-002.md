## 1. Decisions needed for M0

### D1 ⚕ Write paths to the vehicle and devices
- **Change:** `caelum-vehicle` is subscribe-only and has no write API. The cFS status publisher
  moves to `caelum-ground` and uses a telemetry-only packet type. Device writes are allowed only
  through entries in a reviewed register, `docs/write-exceptions.md` (crate, call, standard or ICD
  reference, reason, reviewer). The CI check ships with zero exceptions. Allowed categories:
  (a) Bluetooth SIG control writes needed for acquisition (CCCD notification enable, Record Access
  Control Point, standard measurement-interval writes); (b) serial poll requests defined in a
  device ICD; (c) the wristband alert through the Bluetooth Immediate Alert Service (Alert Level
  0x2A06) only. Crew stations always sound as well, so no alarm depends on the wristband.
  How CAELUM telemetry enters cFS (SBN, CI_LAB or a ground-link gateway) is open item OI-1 in
  `docs/icd/ICD-VEH.md`; until it is agreed, path B emits CCSDS packets to a configurable UDP
  endpoint.
- **Reason:** CLAUDE.md rule 5 and the M0 "no command API" check contradicted F-GND-11 (publisher
  in `caelum-vehicle`), F-ALM-04 (wristband sound) and `04` §1 (SIG control writes).
- **Requirements:** R-SEC-04, new R-SEC-07, R-INT-04, SR-011, SR-015, F-ALM-04, F-GND-11, F-GND-13.
- **Safety:** H-07 reduced (every device write is listed and reviewed; vehicle side has no write
  API). H-01 reduced (the audible alarm never depends on the wristband).
- **Tests:** guard self-tests with planted violations (M0); a register entry for every write (M2,
  M4); crew stations sound with no wristband connected (M4); the publisher cannot build a
  telecommand packet (M10).

### D3 Coverage evidence for the alarm core
- **Change:** MC/DC tooling is dropped. Stable CI gates with `cargo-llvm-cov`: `caelum-alarms`
  ≥ 95 % region coverage, other core crates ≥ 85 % line coverage. A nightly-toolchain CI job
  reports branch coverage for `caelum-alarms` (informational). Compensating measures: exhaustive
  table-driven and property tests per rule, and a documented independent review of
  `caelum-alarms`.
- **Reason:** branch coverage needs nightly Rust, and there is no supported MC/DC tooling for Rust.
- **Requirements:** `02` §4, `09` §1 and §4. **Safety:** H-01 evidence changes from a coverage
  metric to tests plus independent review. **Tests:** coverage jobs (M0), per-rule tests and
  review record (M3).

### D4 Offline build and install
- **Change:** R-OPS-03 reworded: install, run and update with no internet; release builds are
  reproducible offline from a prepared, checksummed tool cache. NSIS and WiX are vendored in the
  cache. WebView2 mode is `offlineInstaller`; `fixedRuntime` is an option for flight builds.
  **Superseded by CR-004:** all Windows release builds use `fixedRuntime` (Tauri 2.12 cannot build
  `offlineInstaller` without network).
  `ort` uses `load-dynamic` with a pinned, checksummed ONNX Runtime binary (M12). Advisory
  databases: an online CI job plus a dated offline snapshot for air-gapped builds. Documented in
  `docs/OFFLINE_BUILD.md`.
- **Reason:** Tauri downloads NSIS/WiX and, by default, WebView2; `ort` downloads its runtime; the
  audit tools download advisory databases.
- **Requirements:** R-OPS-03, F-SYS-06, N-08. **Safety:** H-06 reduced (checksummed cache).
  **Tests:** offline release build from the cache with the network disabled (M0 gate).

### D5 ⚕ Design tokens and accessibility (alarm colours are the ⚕ part)
- **Change:** keep the prototype's look, fix accessibility. Remove `'Google Sans'` from every font
  stack (Outfit bundled via `@fontsource` counts as local). Keep `#D4A017` only as a fill with
  dark text; add `--warning-ink` for amber text; darken `--ink-3`. All text ≥ 4.5:1 and UI
  elements ≥ 3:1 in the light, dark and a new high-contrast theme. Define `--alarm-high` and
  `--alarm-medium` per theme (light starts from `#B42318` / `#B54708`). Restore scrollbars. An
  automated test computes contrast for every token pair used for text or UI elements and fails
  below the thresholds.
- **Reason:** `07` required both a verbatim copy and accessibility checks that the verbatim
  tokens fail (`#D4A017` on white ≈ 2.4:1; `--ink-3` on canvas ≈ 4.0:1).
- **Requirements:** F-SYS-10, R-ALM-02, SR-013, `07` §1 and §5. **Safety:** H-10 reduced.
  **Tests:** contrast test (M0); axe checks (M5).

## 3. Clarifications for later milestones
- **B2 Role matrix:** `docs/ROLE_MATRIX.md` is drafted as the first step of M1 for approval.
  Principles: astronaut = own data; CMO = all crew onboard; flight surgeon = all crew, ground;
  BME = devices, technical alarms, data quality, clinical values read-only; mission control =
  status only; administrator = configuration, no clinical content (separation of duties); device
  gateway = ingest only. Check-in tiers: Private (astronaut only), Medical (CMO + flight surgeon),
  Status (operational level only).
- **B3 ⚕ Rule parameters:** `max_gap_s` per rule (ruleset field); staleness per parameter
  (`stale_after_s`, catalog field). Temperature clear windows equal their fire windows (600 / 300
  s). Baseline rules for heart_rate (at rest), hrv_rmssd, respiration_rate, core_temp, spo2 (at
  rest), weight. Missing activity is `unknown`: the at-rest rule is evaluated (safety first) and
  the alarm's why states "activity unknown". Never default to 0 (new SR-018).
- **B4 ⚕ Rule types and AF:** the M3 engine supports an absence-of-event rule type, tested with
  synthetic event streams; `asystole.critical` is wired to real QRS detection in M7. AF from the
  model is an observe-level notice ("record a 12-lead ECG") until model M2 is `VALIDATED`;
  promotion to warning needs a CR.
- **B5 ⚕ Ground escalation and OPS content:** ground escalation always goes on OPS via path B.
  OPS fields allowed: crew id, priority, alarm category (CARDIO / RESPIRATORY / THERMAL /
  ENVIRONMENT / TECHNICAL), state, escalation stage, timestamps. "Physiology" means any measured
  value, parameter name, rule id or free text; it never goes on OPS. Full detail follows on
  MEDICAL via path A or A'.
- **B6 ⚕ Catalog:** add `body_temp_measured` (with site code; thermometer readings go here, never
  to `core_temp`), `spe_state` (enum), link metrics `rssi`, `packet_loss_pct`,
  `reconnect_count`. Pulse rate uses LOINC 8889-8 (heart rate by pulse oximetry). Every LOINC
  code is verified against the LOINC table before use.
- **B7 Pairing and bonding:** platform modules in M2: Windows (WinRT DevicePairing via the
  `windows` crate), Linux (BlueZ D-Bus via `bluer`), macOS (system pairing on encrypted access),
  plus a guided OS-pairing fallback in the protocol library.
- **B8 Loss of signal:** handled by the store-and-forward queue, not by CFDP. CFDP transactions
  run only during contact windows; the queue suspends and resumes them. Missing pieces are built on
  top of `cfdp-rs` (upstream contributions welcome). M10 gate reworded.
- **B9 UI end-to-end tests:** Windows (reference) and Linux via `tauri-driver`; macOS gets
  component tests only. Consequence recorded by Claude, confirm: `tauri-driver` is a WebDriver
  server and Playwright does not speak WebDriver, so end-to-end tests use WebdriverIO as the
  client; Playwright stays for component and accessibility tests in Vitest browser mode.
- **B10 Platform, crypto wording, time, ruleset keys:**
  - SQLCipher wording fixed: SQLCipher 4 uses AES-256-CBC with HMAC-SHA512 page authentication.
    `aes-gcm` is for the attachment file store.
  - Platforms: Windows 11 and Windows 10 LTSC as the NASA host baseline. Supported LTSC editions
    (checked 2026-10-09 against Microsoft lifecycle data): Windows 10 IoT Enterprise LTSC 2021
    (support until 2032-01-13); Windows 10 Enterprise LTSC 2019 and IoT Enterprise LTSC 2019
    (until 2029-01-09). Windows 10 Enterprise LTSC 2021 (non-IoT) ends 2027-01-12 and is not in
    the baseline. Microsoft lists Edge/WebView2 support for all of these; LTSC 2019 ships without
    WebView2, which the bundled Fixed Version runtime covers (CR-004).
  - Time: leap seconds from a bundled IERS table, updated by signed configuration; CUC epoch =
    CCSDS 1958-01-01 TAI; MET epoch from signed mission configuration (new R-OPS-05).
  - ⚕ Ruleset keys: development keys work only in development builds and show a
    "DEVELOPMENT RULESET" banner; release builds accept only flight keys with a medical approver
    signature (SR-009).

## 6. Open items found while applying this CR (for the medical lead, not decided here)
- **OI-A ⚕ Spot-check readings and persistence.** Persistence is time-based, and a single spot
  reading (PLXS spot-check, BPS, HTS, weight scale) can never last 15–600 s. As written, a spot
  SpO₂ of 80 % never alarms and `baseline.weight` can never fire. Spot-check parameters need their
  own persistence rule (for example a confirmed repeat reading, or immediate evaluation).
- **OI-B ⚕ Fever from a thermometer.** Temperature rules apply to `core_temp` (the F-SIG-05
  estimate). With thermometer readings in `body_temp_measured`, a measured fever raises no
  alarm. Decide whether `body_temp_measured` gets rules (they would be site-dependent).
