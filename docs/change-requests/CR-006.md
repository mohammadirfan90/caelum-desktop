# CR-006: Dependencies for the M1 security core and encrypted storage

- **Status:** approved 2026-10-10 by engineering under the product owner's standing delegation
  ("analyze and choose the best option"). Required by CR-003 §5: crates used in
  `caelum-security`, crypto code or network code need a CR. Not ⚕.
- **Affects:** `caelum-security`, `caelum-store`; F-SYS-01/02/03, R-SEC-01..03.

## 2. Fixed security parameters (engineering decisions)
- **argon2id:** memory 64 MiB, 3 iterations, 1 lane; 16-byte random salt; PHC string stored.
  Above the OWASP minimum while unlocking in well under a second on the reference laptop.
- **Audit chain:** `hash = SHA-256("CAELUM-AUDIT-1" ‖ seq ‖ id ‖ at_tai ‖ actor ‖ role ‖ action ‖
  target ‖ details ‖ prev_hash)`, each field length-prefixed (u64 big-endian), so every field
  including time and position is covered; the Ed25519 signature covers that hash, recomputed from
  the fields at verification; genesis `prev_hash` is 64 zeros. Truncating the end of the chain is
  caught by comparing the chain head with the downlinked copy (M10).
- **Database key:** 32 random bytes, created once per installation and kept only in the OS
  keystore (service `org.chronostrider.caelum`), never in a file.
- **Instance signing key:** Ed25519, 32-byte seed from the OS, kept only in the keystore (entry
  `instance-signing-key`; the database key is `database-key`). A key is created only for a new
  installation; if the database exists and a key is missing, CAELUM stops instead of creating one.
- **Sessions:** auto-lock after 10 minutes idle (configurable), re-authentication valid 2 minutes
  for sensitive actions (`docs/ROLE_MATRIX.md` §4). Timing uses the monotonic clock, so changing
  the wall clock cannot extend a session. Sign-in rules and throttling: CR-007.
- **Test speed:** `argon2` and `blake2` are compiled optimised in development and test builds
  (workspace `Cargo.toml`), so tests use the production parameters.
