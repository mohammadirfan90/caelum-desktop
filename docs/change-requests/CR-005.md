# CR-005: M0 offline-build evidence; physical network-off run moves to M13

- **Status:** approved by the product owner on 2026-10-10 ("go for online and offline both …
  analyze and go for the best option"). Not ⚕ (no alarm or clinical content).
- **Change:** the M0 gate item "a release installer is built from the checksummed tool cache with
  the network disabled and installs with no network" is met by the **network-trap build**:
  `tools/offline/build-offline.ts` verifies the cache, runs cargo with vendored sources and
  `net.offline`, pnpm with `--offline`, and points every proxy-respecting client at a closed local
  port, so any network access fails the build. Evidence: both installers built this way
  (2026-10-10) and both install per machine and run on the bundled WebView2 runtime.
  The run with the network **physically** disconnected moves to M13 (hardening, fault injection on
  the reference laptop), together with the offline install on Windows 10 LTSC 2019.
- **Reason:** the trap already proves the build uses only the cache; disconnecting the developer's
  machine at every gate adds inconvenience without adding much evidence. M13 is where the
  air-gapped campaign runs anyway.
- **Both modes stay supported:** online builds (`install-webview2.ts`, then `pnpm tauri build`) and
  offline builds (`build-offline.ts`); the application never needs a network at runtime.
- **Affects:** `10_BUILD_PLAN.md` M0 gate and M13 prompt. **Tests:** none changed.
