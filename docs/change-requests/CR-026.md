# CR-026: Adapter plug-in SDK (F-ACQ-12)

- **Status:** approved 2026-10-10 by engineering under the product owner's standing delegation.
- **Affects:** `caelum-devices::plugin` (SDK trait and wire format), `caelum-core::plugin_host`
  (isolated-process host), `caelum-core::station::plugins`, `caelum-devices::ble` (vendor
  notifications), `docs/write-exceptions.md` (WX-001).

## 1. Decisions
- **A plug-in is a decoder only.** CAELUM owns the device link; the plug-in receives frames and
  returns readings. It never gets a device handle, so it cannot write to a device (CLAUDE.md
  rule 5).
- **Signed manifest** (kind `adapter-plugin`), stored at `<data dir>/plugins/<id>/`. It states:
  - the plug-in ID and SDK version 1;
  - the executable and its SHA-256, checked before the executable is ever started;
  - the vendor notify characteristic;
  - the only catalog parameters the plug-in may report.
- **Validation:** readings outside the declared parameters are dropped and counted. The rest go
  through normal ingest (units, plausibility, time, SR-017) and alarm evaluation.
- **Isolated process:** one JSON line per frame over stdin/stdout, with a 250 ms limit per
  frame. A crash or a late or malformed reply drops that frame, and the process restarts on the
  next one.
- **Where the host lives:** the host writes only to the child process's pipe, which is local IPC
  and not a device write. So it lives in `caelum-core`, outside the device crates that the write
  guard covers.
- **WX-001:** notifications may be enabled only on the data characteristic a signed plug-in
  manifest declares (a CCCD enable, category a).

## 2. F-ACQ-13 (vendor smart-garment adapters)
Astroskin-class garments use proprietary protocols that are not public. An adapter is written
against the vendor's interface control document once it is supplied. None is guessed.
