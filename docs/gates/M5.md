# M5 gate evidence: UI shell and design system

Gate (docs/10_BUILD_PLAN.md, M5): axe accessibility checks pass (Vitest browser mode); contrast
test passes; keyboard-only walkthrough; 200 % text and glove mode screenshots reviewed; no screen
shows a number without a data source; no user-visible string outside the localisation catalog.

| Gate item | Evidence | Result |
|---|---|---|
| axe checks pass (Vitest browser mode) | `ui/tests/a11y/screens.browser.test.tsx`: axe-core with the WCAG 2.0/2.1 A and AA rules, contrast measured on the rendered page. Covers sign-in, first-administrator enrolment, lock screen, emergency view, alarm bar with escalation tracker, ruleset banner, primitives gallery and the signed-in shell, each in light, dark, high contrast and 200 % text with glove mode (32 cases). Self-test "detects violations": an unlabelled input and low-contrast text must be reported, so the check cannot pass while doing nothing. The keyboard walkthrough also runs axe on the whole window after each step. CI runs `pnpm -C ui test:a11y` in the `ui` job; the trace runs it too. | PASS |
| Contrast test passes | `ui/tests/contrast.test.ts`: every token pair in `contrast-pairs.ts`, every theme, text ≥ 4.5:1 and UI elements ≥ 3:1, plus WCAG reference values and a guard against unmeasurable colours. Also axe `color-contrast` on the rendered screens (row above). | PASS |
| Keyboard-only walkthrough | `ui/tests/a11y/keyboard.browser.test.tsx`, real key presses in Chromium with no pointer: Tab reaches the skip link first and Enter moves to the content; sign-in by typing and Enter; focus moves to the new content after each window change; Settings reached by Tab and opened with Enter (`aria-current`); theme changed with arrow keys and glove mode with Space; an incoming alarm acknowledged from the alarm bar with Shift+Tab and Enter; the emergency view opened and closed with no sign-in (SR-014). Every focused control must show a focus outline of at least 2 px. | PASS |
| 200 % text and glove mode screenshots reviewed | Every screen at 200 % with glove mode: `docs/gates/M5-screenshots/*.png` (CI artifact `ui-screenshots` on every run). Review findings, all fixed in this step: (1) button and label text was set in px and did not scale (`tokens.css` now uses rem); (2) the alarm bar cut the alarm title short ("Severe low b…"); it now wraps and the bar reflows; (3) after signing in, focus fell back to the start of the page. Tests now cover all three: "text doubles at 200 % and nothing is clipped", with one case per screen comparing every text element's computed size at 100 % and 200 % and failing on any clipped text, and the focus assertions in the walkthrough. Each was shown to fail with the old code. | PASS |
| No number without a data source | `ui/tests/primitives.test.tsx` › "shows a number only with its source and time" and "shows NO DATA, STALE and SIGNAL UNUSABLE instead of numbers"; the `Reading` type of `Stat` requires a source and a time, and an empty source or a non-finite value is shown as NO DATA. The shell footer shows NO DATA for links not available yet (`App.test.tsx` › "signs in and shows the shell…"). | PASS |
| No user-visible string outside the localisation catalog | `ui/tests/i18n.test.ts`: every `.tsx` in `ui/src` is parsed with the TypeScript compiler; JSX text and the aria-label, title, alt, placeholder and label attributes must not contain letters as literals; with a self-test. | PASS |

Also delivered in M5: the desktop layout of docs/07 §3 (ruleset banner, alarm bar, nav rail by
role per ROLE_MATRIX §6, crew strip, content, status footer); LevelGlyph with the technical square;
NoData, Stat, Card, SectionHead, EmptyState; AlarmBar and EscalationTracker; themes, text size to

(CR-007 §4), lock and break-glass entry (`App.test.tsx`).
