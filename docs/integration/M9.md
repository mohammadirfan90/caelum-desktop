# M9 integration notes: vehicle bridge (for the lead)

`caelum-vehicle` is complete and self-contained (F-ENV-01, F-ENV-02, F-ENV-03, F-GND-11
subscribe side, R-INT-04, F-ACQ-11). It does no storage, alarm evaluation or IPC. This note lists
what `caelum-core`, `caelum-domain`, `src-tauri`, `ui` and the docs need. Decisions: CR-015.
Interface: ICD-VEH v0.2.

## 1. Starting the receiver (caelum-core)
```rust
let config = caelum_vehicle::VehicleConfig::from_toml(verified_bytes)?; // bundle kind "vehicle"
let mut rx = caelum_vehicle::VehicleReceiver::bind(
    config,
    leap_seconds.clone(),        // signed LeapSeconds in force
    mission.met_epoch,           // MetEpoch from signed mission configuration (R-OPS-05)
    move || clock.now_tai().ok(), // station TAI clock
).await?;
loop {
    match rx.recv().await {
        Ok(decoded) => { /* §2 for decoded.readings; log decoded.rejections by code() */ }
        Err(caelum_vehicle::RecvError::NoStationTime) => {} // counted in rx.no_station_time()
        Err(caelum_vehicle::RecvError::Io(e)) => { /* technical alarm, back off, rebind */ }
    }
}
```
- Run it as one supervised task, started only when a verified `vehicle` bundle is in force. With
  no bundle there is no receiver and the Environment screen shows NO DATA.
- `recv` is cancel-safe, so it can sit in a `select!` with shutdown. The receiver keeps the
  socket private and has no send API. Do not add one: the CI guard and
  `tests/no_send_api.rs` fail on it.
- Applying a new bundle means dropping the receiver and binding a new one. Counters and the
  correlation window restart.
- The receiver needs tokio's `net` feature, which caelum-vehicle enables itself.

## 2. Storing readings (classification `measured`, source `vehicle`)
Each `VehicleReading` carries the canonical value and unit, the calibrated original,
`measured_at`, `received_at`, `met`, `time` (`Vehicle { offset_ns, exact }` or
`ReceiptUnsynchronised`), quality, mode, MID and message name, and a `subject`:
- `Subject::Crew(id)` (personal dosimeter, exercise session): store for that crew member.
- `Subject::Cabin { location }` (atmosphere, area dosimeter, SPE state): the rule engine
  (`caelum_alarms::engine::Input`) is per crew member. Recommended: store one observation per
  active roster crew member, because the cabin environment applies to everyone aboard. This
  way `co2.warning` and `o2.critical` raise ENVIRONMENT alarms through the normal per-crew
  escalation, and each crew member's correlation view has the data.
- Device: register one pseudo-device per configured MID (adapter `vehicle`, model = message
  name, serial = `0xMID`), assigned to no crew member. Use its `DeviceId` as `device_id`. The
  staleness monitor then tracks each MID, and inbound gaps make values STALE and raise the
  technical alarm (SR-004, ICD-VEH §9).
- Build `caelum_ingest::Observation` directly; do not go through `ingest()`, because it requires
  a device assignment. Values are already validated, converted and range-checked against the
  catalog. Set `classification: Measured`, `provenance.original` from `reading.original`, and
  `provenance.time`:
  - `TimeSource::Vehicle` → `DeviceCorrected { offset_ns, residual_ns: 0 }`, or add a
    `Vehicle` variant;
  - `ReceiptUnsynchronised` → the same name.
  Record source `"vehicle"` (`caelum_vehicle::SOURCE`) in the context JSON.
- Then call `Station::observe(&obs)`. `VehicleValue::State` (SPE) maps to `Value::State`.
- `spe_state` (domain, CR-015 §4): change the catalog entry from
  `ValueType::EnumPending(..)` to `ValueType::Enum(&["none", "watch", "warning", "in_progress",
  "all_clear"])` (= `caelum_vehicle::SPE_STATES`), and update the test
  `spe_state_values_are_pending_not_invented`.

## 3. Config bundle kind `vehicle`
Same envelope, keys and trust policy as the crew roster (CR-012 §2). Signed with
`caelum-ruleset-signer sign-config` and kind `vehicle`. Applied by an Administrator after
re-authentication (new command `config_apply_vehicle`, ROLE_MATRIX §4 row like the roster),
stored in `config_bundle` and audited (`config.apply`, version, digest). Format (all keys
required unless marked optional; unknown keys refused):

```toml
[vehicle]
version = "2026.10-1"

[link]
listen = "0.0.0.0:50110"           # local bind address
framing = "ccsds"                  # "ccsds" | "sbn"
header = "cfe7"                    # "cfe7" (payload at 16) | "cfe6" (payload at 12)
allowed_sources = ["192.0.2.10"]   # vehicle addresses; non-empty
# sbn_peers = [1, 2]               # optional, SBN only: allowed ProcessorIDs

[time]
epoch = "1980-01-06T00:00:00"      # vehicle clock epoch
scale = "tai"                      # "tai" | "utc"
clock_state_max_age_s = 30

[[crew]]                           # optional; required if a message has crew_field
vehicle_id = 1
crew_member = "<roster UUID>"

[[message]]
mid = 0x0805
name = "CFE_TIME_HK_TLM"
kind = "time"                      # environment | radiation | exercise | time
byte_order = "little"              # little | big
clock_state = { offset = 2, type = "u16", mask = 0x8000 }
leap_seconds = { offset = 6, type = "i16" }        # optional

[[message]]
mid = 0x0C40
name = "ECLSS_CABIN_ATMOS_TLM"
kind = "environment"
byte_order = "little"
location = "cabin"                 # optional area label
# crew_field = { offset = 0, type = "u8" }   # radiation (personal) / exercise (required)

[[message.field]]
parameter = "cabin_co2"
offset = 0
type = "f32"                       # u8 i8 u16 i16 u32 i32 f32 f64
unit = "mm[Hg]"                    # UCUM, a catalog unit
# scale = 1.0                      # optional calibration
# bias = 0.0
validity = { offset = 20, type = "u8", mask = 0x01 }   # optional
# states = [{ code = 0, state = "none" }, ...]       # spe_state only
```
The full reference table is `crates/caelum-vehicle/tests/fixtures/reference.toml`. It is a test
fixture whose crew UUIDs are test identities; the flight table comes from the vehicle mission
database (ICD-VEH OI-7).

## 4. Environment screen (F-ENV-01..04, docs/07)
Commands (all authenticated; Astronaut sees own crew-scoped data and cabin data; CMO, Flight
Surgeon, BME all; MCC none, because the environment values are MEDICAL_ONLY channels):
- `environment_latest`: per cabin parameter (`cabin_co2`, `cabin_o2`, `cabin_pressure`,
  `cabin_temp`, `cabin_humidity`, `radiation_dose_rate`, `radiation_dose_cumulative`,
  `spe_state`) the newest value, unit, location, measured time (UTC and MET), quality, time
  source and status (live / STALE / NO DATA). Also personal dose rate and cumulative dose per
  crew member in scope.
- `environment_trend { parameter, window ≤ 24 h }`: the series, as `vitals_trend`.
- `exercise_sessions { crew, window }`: load (W), duration (min), measured time.
- `vehicle_link_status`: from `rx.stats()`, `rx.correlation(now)` and
  `rx.no_station_time()`. Shows datagrams, readings, drops by code, per MID packets, sequence
  gaps and last receipt; clock state (`not_configured`, `unknown`, `set`, `not_set`, `stale`),
  receipt−vehicle offset (latest, minimum, maximum), latest vehicle time and its MET, and
  vehicle vs station TAI−UTC (flag a mismatch). Technical health, no physiology, so it can also
  feed OPS technical status.
- Correlation view (F-ENV-04): `correlation { crew, window, parameters[] }` returns aligned
  series of chosen environment parameters and that crew member's physiology (for example
  `cabin_co2` with `respiration_rate` and `heart_rate`), plus ENVIRONMENT alarms and exercise
  sessions as event markers, on one TAI time axis shown as UTC and MET. Points with
  `receipt_unsynchronised` time are marked.
- Event `environmentChanged` (no values), as `observationsChanged`.

## 5. Tests the lead should add at integration
- Station-level: the end-to-end source → receiver → `Station::observe` with `cabin_co2` above
  `co2.warning` for 900 s raises an ENVIRONMENT alarm (M9 gate). Also `cabin_o2` below 16 kPa
  for 30 s for `o2.critical`. `crates/caelum-vehicle/tests/e2e_udp.rs` already proves that the
  receiver delivers a CO₂ value above the ruleset's `co2.warning` fire threshold, which it reads
  from `ruleset.toml`.
- The CI write guard passes with `caelum-vehicle` in scope (no change needed).
